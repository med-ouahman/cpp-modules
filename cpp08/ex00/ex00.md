# Exercise 00 — Easy find

## Goal

Write a **function template** `easyfind` that searches for the first occurrence of an integer inside any sequential container of integers. If the value is not found, it throws an exception.

---

## Concepts Covered

### Function Templates with a Container Type Parameter
The template parameter `T` is constrained by usage: the function calls `T::begin()` and `T::end()`, so `T` must be a container. No explicit `concept` keyword exists in C++98; the constraint is implicit and enforced by the compiler when you pass a non-container type.

```cpp
template <typename T>
typename T::iterator easyfind(T &container, int value);
```

The return type `typename T::iterator` requires the `typename` keyword because `T::iterator` is a *dependent name* — the compiler cannot know at parse time whether it is a type or a value.

### `std::find` from `<algorithm>`
`std::find(first, last, value)` performs a linear scan of `[first, last)` and returns an iterator to the first element equal to `value`, or `last` if not found. It works on any input iterator range, making it compatible with all sequential STL containers.

### Exception on Failure
When `std::find` returns `container.end()`, no match exists. Following the convention of STL functions like `std::map::at`, the function throws `std::runtime_error`. Callers must wrap the call in a `try`/`catch` block.

---

## Design Decisions

- **Return type is `typename T::iterator`**: the caller receives the position directly and can use it to inspect surrounding elements — not just the found value.
- **`std::find` instead of a hand-written loop**: this is the entire point of the exercise. Using the algorithm demonstrates idiomatic C++ style.
- **No support for associative containers** (`std::map`, `std::set`): the subject explicitly excludes them. Their iterators expose `std::pair` values, not plain integers.
