# Exercise 02 — Identify Real Type

## What it is

Given a `Base*` or `Base&` pointing at an unknown derived object (A, B, or C),
identify the actual runtime type and print it, without using `typeid` or `<typeinfo>`.

## Cast used: `dynamic_cast`

`dynamic_cast` performs a safe runtime downcast within a polymorphic hierarchy.
It requires at least one virtual function in the base class — the virtual destructor
in `Base` qualifies.

Two usage patterns depending on the function overload:

### Pointer version — returns nullptr on failure
```cpp
void identify(Base *p) {
    if (dynamic_cast<A *>(p)) { std::cout << "A"; }
    ...
}
```
No exception is thrown. A failed cast simply yields a null pointer, which is falsy.

### Reference version — throws std::bad_cast on failure
```cpp
void identify(Base &p) {
    try { (void)dynamic_cast<A &>(p); std::cout << "A"; return; }
    catch (...) {}
    ...
}
```
Pointers are forbidden inside this overload, so try/catch is the only mechanism.
`std::bad_cast` (from `<typeinfo>`) would normally be the specific catch type,
but since `<typeinfo>` is forbidden we catch `...` instead.

## Why not static_cast or reinterpret_cast?

Neither performs any runtime check. Downcasting with them on a wrong type produces
undefined behaviour — no diagnostic, no nullptr, just a corrupted pointer.
`dynamic_cast` is the only cast designed for this exact use-case.

## Files

- `Base.hpp` / `Base.cpp` — polymorphic base
- `A.hpp`, `B.hpp`, `C.hpp` — derived classes
- `functions.hpp` / `functions.cpp` — generate / identify implementations
- `main.cpp` — test program
